# Moonlight 기능 + UI/UX 점검 (2026-07-23)

방법: 코드 정적 분석(백엔드 app.py 1734줄 / 프론트 app.js 3153줄 전수 매핑) + 라이브 브라우저 워크스루(uvicorn 기동, DOM·네트워크 실측) + AI 실호출 스모크. 등급: **Critical**(동작 깨짐·데이터 손실) / **Major**(품질·보안 실위험) / **Minor**(다듬기).

브라우저 페인이 화면에 표시되지 않아 스크린샷 대신 DOM·computed style·네트워크 로그 실측으로 검증함.

---

## Critical — 1건 (수정 적용, 최종 검증 대기)

### C1. AI 기능 전멸: 모든 `claude -p` 호출이 502로 실패
- **증상(실측)**: 문장 연결 자동 정렬 `POST /align/page` 2건 연속 502, 선택 번역 `POST /api/ai/selection` 502. 에러 바디: `AI 호출 실패: SessionEnd hook [transcript-mirror.cjs] failed: Hook cancelled`.
- **원인**: Moonlight가 띄우는 헤드리스 `claude -p`가 사용자 **전역 훅 스택을 상속 실행** — SessionStart(memory-bank 동기화 vbs 등) + SessionEnd(transcript-mirror, 2026-07-23 배선). 훅 자체는 fail-open이지만 CLI가 훅을 취소하면("Hook cancelled") returncode≠0 → `ask_claude`(app.py:131)가 502로 변환. 세마포어 4로 **동시 호출**되는 구조(번역 2워커, prepPaper 4종 병렬)라 SessionEnd 미러들이 같은 라이브 jsonl을 같은 목적지로 경쟁 복사 → 취소 유발. 훅 단독 실측 1.9초/7,403파일 체크 — 취소 없이도 **매 AI 호출마다 이 비용을 공짜로 지불**하고 있었음.
- **핵심 사실**: 이 세션들은 `--no-session-persistence`라 transcript가 안 남음 → 훅이 미러링할 대상 자체가 없음. 훅은 순수 비용 + 실패 원인.
- **수정(적용됨)**: app.py `ask_claude` cmd에 `--settings '{"disableAllHooks":true}'` 추가 — Moonlight 서브프로세스에서만 훅 비활성. 부작용 없음(훅이 할 일이 없는 세션), 매 호출 수 초 절약 + 취소 실패 제거.
- **검증 상태**: 코드 적용 완료. 서버 재기동이 권한 분류기에 차단되어 **최종 실측(선택 번역 200 확인) 대기** — run.bat 재실행 후 아무 논문에서 드래그→번역 1회로 확인 가능.
- **참고**: 훅 쪽 근본 개선(transcript-mirror SessionEnd를 detach 실행으로 전환 — 모든 헤드리스 소비자에 이득)은 진행 중인 2PC 검증 작업(wip/2pc-transcript-mirror-verify.md)과 겹쳐 이 세션에서 건드리지 않음. 별도 작업 칩으로 분리.

## Major — 3건

### M1. CSRF·DNS-rebinding 방어 부재 + 업로드 크기 무제한
- Origin/Host/Referer 검증, CORSMiddleware, TrustedHostMiddleware 전무(app.py 전체 grep 확인). `POST /api/papers`(multipart)는 preflight 없는 단순 요청 — 브라우저에 열린 악성 페이지가 라이브러리에 임의 파일 블라인드 업로드 가능. JSON POST들(chat/notes/keypoints 등)도 Starlette `req.json()`이 Content-Type을 안 보므로 `text/plain` 단순 요청으로 preflight 우회됨. DNS rebinding 시 same-origin 취급되어 읽기까지 뚫림. 업로드 크기 상한 없음(썸네일만 400KB 캡, app.py:291).
- **권고**: ① Host 헤더가 `127.0.0.1:8766`/`localhost:8766`가 아니면 403 미들웨어 1개(rebinding 원천 차단, ~10줄) ② 업로드 상한(예: 100MB).

### M2. meta.json 잃어버린 갱신 — UI에서 실제 도달 가능한 RMW 경합
- 락 자산: TEXT/FIG/CMP/TRANS/ALIGN_LOCK 존재. 그러나 chat·notes·highlights·keypoints·glossary·questions·patch_paper·put_text·extract_metadata는 무락 read→mutate→write. `put_text`는 같은 text.json을 쓰는 `vision_text`(TEXT_LOCK 사용, app.py:610)와도 비대칭.
- 도달 경로(실재): 첫 열람 시 `PATCH status=reading`(app.js:629) + `POST /metadata`(AI 수 초, app.js:940)가 미대기 발사 — 그 사이 사용자가 태그/완독 변경(app.js:305,320) 시 한쪽 쓰기 소실. 원자적 replace라 파일 파손은 없고 필드 1개 소실 수준.
- **권고**: meta.json 전용 락 1개(또는 공용 `META_LOCK`)로 patch_paper·put_text·extract_metadata 감싸기. chat 이중발사는 UI가 이미 차단(전송 버튼 disabled, app.js:2256).

### M3. `md()` 새니타이저 — 거르는 목록(denylist)의 실틈
- 현행: script/iframe/object/embed/link/style 태그, `on*` 속성, `href`의 `javascript:` 제거. AI 출력 렌더 6개소(요약·채팅·선택·그림·번역·노트) 모두 md() 경유 일관 확인, esc() 스팟체크 5개소 전부 통과(우회 없음).
- 틈: 인라인 `style="background:url(...)"` 미제거(CSS 비콘), `javascript:` 검사 대상이 `href`뿐(src·formaction·xlink:href 미검사), `srcdoc` 미검사. 공격 경로 = 외부 PDF 원문을 AI가 그대로 재현(번역·인용은 원문 보존이 사양)하는 간접 주입 — 논문을 임의 출처에서 받는 앱 특성상 개연성 있음.
- **권고**: 태그 denylist는 유지하되 속성 검사를 allowlist로 뒤집기(허용: href(http/https/#)·src(data:image·同 origin)·class·나머지 제거). ~15줄.

## Minor — 8건 (다듬기 우선순위순)

1. **정렬(문장 연결) 대기 UX**: 구경로 ~100초/쪽(app.js:2789 주석) 동안 피드백 = 버튼 라벨 `10/15` 카운터뿐. 취소 = 같은 토글 재클릭인데 라벨 없음. **페이지별 실패가 `A.err`에 쌓이지만 어디에도 표시 안 됨(사장된 상태값, grep 확인)** — 이번 502 전멸도 UI상 무음이었음. 번역 실패의 "다시 시도" 버튼 패턴을 정렬에도 적용 권장. (완화: 신규 번역은 번역 호출에 정렬이 동봉되어 이 경로 자체가 레거시 백필 전용.)
2. **a11y**: 인스펙터 탭에 role=tab/aria-selected 없음(app.js:3026, 라이브 확인 role=null). sel-pop 버튼 menuitem 없음, 다이얼로그 포커스 트랩 없음(Tab이 모달 밖으로 탈출). 툴바 아이콘 aria-label은 잘 되어 있음.
3. **테마 auto 복귀 불가**: 한 번 토글하면 light↔dark 2-상태 고착(applyTheme:144 — auto 저장 경로 없음). 라이브 실측 auto→dark→light→dark. 사이클에 auto 포함 또는 롱프레스=auto 권장.
4. **질문(추천 질문) 매몰**: 채팅 탭을 열어야만 칩으로 노출. 요약 탭 하단 등 1차 노출면 추가 고려.
5. **그림·표 해설 휘발**: cite-pop 팝오버로만 표시, 저장 안 됨(서버 캐시는 있음 — figures.json). 캐시를 읽는 갤러리/탭이 없어 재조회 불가. 캐시 조회 UI 1개면 기존 데이터가 살아남.
6. **미사용 Inter 폰트 3종 72KB**(vendor) — CSS 참조 0(grep 확인). 삭제 가능.
7. **문서 괴리**: README 기능표가 구현의 절반 누락(키포인트·용어집·질문·그림해설·OCR·메타데이터·서재검색·서재질문·비교·Obsidian·Zotero·병렬 뷰). README 트러블슈팅 "글자가 안 긁힘→OCR PDF를 쓰라"는 **내장 vision-OCR(app.py:597)과 모순**. 스펙 상태 "Phase 1 구현 중"은 낡음 — Phase 1 완료, 단 스펙의 Phase 2(highlights/align 엔드포인트)는 미구현이고 지금의 "문장 연결"은 별개 메커니즘(align.json)임.
8. **인스펙터 자동 접힘 vs 수동 토글 충돌 가능성**: 코드 주석이 스스로 인정(S.inspAutoHid). 병렬 진입 시 자동 접힘은 라이브에서 정상 동작 확인.

구조 노트(등급 외): app.js 단일 3153줄·전역 S·innerHTML 재렌더 — 현 규모에선 동작하나 기능 추가마다 `reapplyAllHighlights`류 복원 핵이 늘어나는 구조. 당장 손댈 필요 없음.
